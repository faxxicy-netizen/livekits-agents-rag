# AI 辅助编程反思与开发记录

## 使用的工具与分工

本项目使用 Codex 进行需求拆解、代码生成、文档查询和迭代验证。用户主导了本地部署约束、外部 LLM 选型与关闭思考的要求。Codex 实现 Python API、LiveKit Agent、本地语音适配器、React 界面、检索、持久化、测试和运行脚本。

本文记录的是本次协作实际发生的事情，不代表候选人已经独立掌握所有代码。提交前应自行阅读关键文件，实际演示并补充个人理解，能解释每一项设计决策。

## 关键设计决策

1. 用户明确要求本地音频房间，因此使用官方 Windows LiveKit Server；WebRTC 传输与模型 API 分开，LLM 使用 DeepSeek Flash。
2. 本机没有 Docker，作业允许 TXT/Markdown 与任意检索实现，因此第一版直接使用中文分词、BM25 和稀疏 TF-IDF，并通过统一接口保留 Dify 适配器。
3. LLM、STT、TTS 分别配置。第一版语音模型均在 CPU 推理；用户指出 VITS 音色与语速不满意后，按 RTX 3060 Ti 8GB 的实际机器改用 Kokoro 中文版 GPU 合成，STT 保留 SenseVoice CPU。
4. 最终答案与来源 ID 采用 JSON 输出，后端校验引用，然后只把正文送进语音合成。
5. 以会话 ID、轮次 ID、SDK 消息 extra 管理数据，防止打断期间出现来源错绑。语音历史使用实际播报转写，并保留打断标记。
6. 用户希望展示语义 RAG 与向量数据库后，加入本地 Qdrant 独立服务和 BGE 中文 CPU embedding，默认使用 RRF 混合检索。API 与 Agent 共享服务，避免嵌入模式的跨进程文件锁问题。
7. 资料从固定目录切换为数据库管理：支持文件上传、文本修改和删除；默认空库，示例需显式导入。向量先写入，再发布正文版本，检索按当前版本过滤；长期运行的语音检索器也会检查知识库变更。

## 实际遇到的问题与修复

- Windows System32 中存在旧 `onnxruntime.dll`，使 sherpa 新版 API 加载失败。修复为仅在本 Python 进程中优先加载虚拟环境内的 DLL，没有修改系统文件或全局 PATH。
- 工作目录包含中文，OpenFST 的原生路径读取失败。语音模型适配器使用项目相对路径或 Windows 短路径，支持从项目根目录启动。
- 早期围绕路由器示例增加了型号过滤、规则式追问改写、别名替换和专门的默认业务配置。扩展到 IoT 等其他资料时，这些假设会误伤正常检索，已全部从应用逻辑移除。检索使用用户原文，历史仅参与模型理解，范围过滤只依赖知识库和文档版本。
- 本地 TTS 曾为示例型号和网络缩写做读法替换，也已移除。术语由模型自行处理，接受局部读音或召回效果下降，避免业务含义被程序改写。
- 仅在提示词里要求 JSON 不够稳定，语音端到端测试中曾出现普通文本回复。启用 DeepSeek 的 JSON 输出约束，并继续校验证据 ID。
- 多轮历史中的 assistant 消息曾使用普通文本，DeepSeek JSON 模式返回大量空白。将历史回答也序列化为同样的 JSON 结构，实际五轮生成验证通过。
- 原始 VITS 的合成速度快于播放速度，但整段返回、音色和说话节奏仍不理想。响应速度、首段等待和主观音质需要分别评估；不能仅用 RTF 小于 1 就认为体验达标。新合成器提供预热、分句输出和可配置语速，并生成同文本试听文件。
- Codex 内置浏览器与新版 LiveKit 默认单 PeerConnection 模式出现配置兼容问题，改用 SDK 支持的双连接模式，并通过不启用麦克风的真实连接诊断验证。
- Windows 虚拟环境 Python 是启动器，会产生实际 Python 子进程。启动/停止脚本增加启动时间校验和子进程处理，避免只停启动器后遗留服务。
- 窄屏隐藏右侧栏后引用无法查看，补充来源弹窗，并用浏览器实际点击验证。

用户随后明确要求停止前端多尺寸适配，后续工作集中到本机中文语音合成。

## 验证方式与局限

离线测试覆盖真实检索、通用查询保留、知识库与版本隔离、历史持久化、访问令牌权限、来源校验和故障区分。语音检查实际运行本地模型；WebRTC 检查用合成输入通过真实 LiveKit Server、真实模型 API 和本地语音引擎测试，不读取人的麦克风。

固定问题集只包含模拟产品，规模有限，命中率不能代表真实企业文档表现。真人口音、噪声、扬声器回声、语音自然度和现场设备权限应单独测试。Dify 适配器尚需外部实例验证。

新增向量检索阶段按用户要求不再执行完整语音端到端验证；实际检查了 Qdrant 的文档上传、跨进程检索、修改后清理旧向量、删除后不再召回，并验证了浏览器操作。之前固定 20 题的报告不代表新向量实现的评估结果。小型中文模型的相似度阈值需要结合实际语料调整，向量相近也不等于证据足够回答。

AI 能快速生成跨组件初稿，但框架版本差异、原生依赖、异步取消和语音识别误差需要实际运行才能发现。开发中优先用可验证的输入输出约定和小型验收场景约束生成代码，再根据失败结果修改实现。
